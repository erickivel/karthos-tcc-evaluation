## Design

1. Preserve failed campaign evidence. Apply the existing VM userinfo-email scope and watchdog networks.updatePolicy correction, including the deployed reused foundation custom role, and read back effective configuration.
2. Bootstrap one explicit controller ClusterRoleBinding to cluster-admin inside each UID-verified, run-owned, temporary evaluation cluster. This is scoped to these disposable clusters; do not grant project Owner/container.admin or transfer operator credentials. A local operator helper reaches the private API through a bounded IAP SSH tunnel through the owned controller VM. TLS verifies the observed cluster CA and private endpoint; operator access token stays in local memory. Recheck cluster UID/ownership and active project lease immediately before mutation; refuse conflicting bindings, unexpected principals, or TLS mismatch. Binding receipt records cluster UID, controller identity, binding UID and scope.
3. Before any application setup, runtime waits only for this named bootstrap binding (bounded 600 seconds per cluster and cleanup cutoff). Emit an authorization-required event. This is an explicit bootstrap handshake, not a retry after an actual authorization denial. After binding exists, require expected authenticated email via SelfSubjectReview; verify effective permissions through SelfSubjectAccessReview plus a disposable, uniquely owned RBAC create/update/delete probe. A denial or malformed response is fatal, with evidence, and never receives an unchanged operational retry. Repeat the gate on each fresh cluster UID. No workload traffic is generated by the probe.
4. Handle later explicit authorization-denied command errors as nonretryable configuration failures, preserving first-attempt diagnostics and exports. Do not treat ordinary HTTP403 application traffic as an infrastructure exception.
5. Before billable provisioning, verify deployed watchdog permission and precise run quarantine bindings. Include both bootstrap allowances in the full time forecast. Rebuild frozen controller/source artifacts, preserve product/scientific hashes, record updated cumulative cost estimate and cleanup reserve. Do not launch unless within BRL1200 including both prior failures.
6. Operator monitors the fresh run and bootstraps each newly observed owned cluster UID. First binding can be installed before controller handoff; second is installed during the explicit runtime bootstrap handshake. Never bind a recreated cluster merely by name; verify fresh UID and current-run creation evidence. Run at most the approved fourteen windows, existing history, and bounded operational retry policy.
